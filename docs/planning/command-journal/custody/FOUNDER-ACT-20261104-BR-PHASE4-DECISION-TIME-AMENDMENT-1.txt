M1. A3 is replaced by: "A3. What the record holds. The control plane's room export, which the runner already reads into the run's record, gives every lifecycle event its committed_at. The control plane alone writes it, and no caller can set it. It is the database's now() when the appending transaction began (the column's default; the insert does not set it): after the request reached the control plane, and before the transaction waited on its locks, replayed the room and wrote the event. Each of those statements is bounded by the control plane's statement_timeout (10 s in the code's default), so committed_at precedes the commit by at most that one transaction's length. The plan's T3 (plan.submitted) opens plan_review; my decision is T4, T5 or T22."

M2. B2 is replaced by: "B2. The judgment. In packages/run-harness/src/phase4/run-unit.ts, a decision event (plan.revision_requested, plan.approved, founder.cancel) decides a plan under review when the latest of plan.submitted, plan.revision_requested and plan.approved before it in the record is a plan.submitted; that plan.submitted opens its time. For each decision that decides a plan under review: if the decision's committedAt is more than the set's decisionTimeoutMs after that plan.submitted's committedAt, the run is interrupted with founder_decision_timeout, the code the runner's flag already gives; if either event lacks committedAt, the run fails with decision_time_unrecorded. A founder.cancel that decides no plan under review (a cancel before any plan, or while the room plans again after a revision) is not timed: B5's 4 hours run only from plan_review. A plan.revision_requested or plan.approved that decides no plan under review fails the run with decision_time_unrecorded. Every other part of the judgment is unchanged, and the runner's own flag still applies."
