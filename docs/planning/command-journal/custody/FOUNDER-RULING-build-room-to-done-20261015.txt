Part B: The five decisions
B1. Room binding. A runtime room is the execution locus of exactly one lifecycle room's build. The binding is recorded by a new thirtieth lifecycle event, appended when Phase 5 first places a build in a runtime room, whose payload carries the lifecycle room id, the runtime room id and the Gateway id, committed in the same transaction as the journal record. T5 and its payload are not changed. A runtime room's CLOSED occupancy is a precondition of T17. This is an amendment of DEC-20260815-11's closed vocabulary; its implementation is Phase 5 work and is not authorized by this ruling.
B2. Room-status consumption. madventures-tui consumes packages/room-status by a vendored copy, pinned to a named Build Room commit, with a check in madventures-tui's CI that fails when the vendored bytes differ from that commit's. A git dependency is not used, because it needs a package manifest and lockfile changes that need their own authorization. madventures-tui mounts RoomStatusBand from the same projection, so that the terminal and every other surface use one vocabulary.
B3. Per-room ceiling. The ceiling is exclusive, as the code enforces it today: a request is refused when spent + reserved + requested reaches the ceiling. This is admission control and errs closed. DEC-20260815-16 clause 2 is read that way from this ruling. The code is unchanged; the test pinned as "CURRENT BEHAVIOUR, semantics unresolved" is renamed to state the settled rule, and docs/phase-2-known-limits.md section 9 is closed, both in the Phase 4 pull request.
B4. Step-up authentication. Step-up is needed for T15, which is Phase 6 work, not Phase 5. I bind the mechanism now so that it does not block Phase 6: a time-based one-time code (TOTP), entered at the moment of the authority-bearing act and verified at the control plane, never by a client surface. Enrollment of the TOTP secret is a separate act of mine. This binds clause 2 of DEC-20260815-07 for the TUI and projector surface; Supabase sign-in in clause 1 stays deferred with the web tier.
B5. Founder surface for the MVP. The MVP surface is the TUI plus the projector relay, which reaches S6 (approve a plan, answer, or authorize from a phone browser) without a web tier. DEC-20260815-08's deferral of the web tier stands. Telegram is named the first surface after the MVP: it may render and relay, and it never originates an authority-bearing act (DEC-20260815-13 clause 2).
