## Part A: Basis

A1. **What B2 ruled.** On 2026-10-15 I ruled that madventures-tui consumes Build Room's `packages/room-status` by a vendored copy pinned to a named Build Room commit, with a check in madventures-tui's CI that fails when the vendored bytes differ from that commit's; that no git dependency is used; and that madventures-tui mounts `RoomStatusBand` from the same projection, so that the terminal and every other surface use one vocabulary. C5 directed the builder to draft this commission under this repository's approval record. It was not drafted until now.

A2. **What exists at the drafting base.**
1. Build Room `packages/room-status/src/` has five files: `index.ts`, `vocabulary.ts`, `status.ts`, `store.ts` and `projection.ts`. It carries no package manifest and is not a workspace member. `projection.ts` imports only types from `../../gateway-protocol/src/ipc-v2.js`, a standalone file with no imports of its own that refers to Node's `Buffer` type. The bytes of `packages/room-status/` are identical to those at Build Room `81d1203e6c0c5382bcf2773d61eed5f0dde4f8ee`, a branch head that is not on `main`; `ipc-v2.ts` differs from that commit by the CreateRoom change, which reached `main` in `57fbcea`.
2. `apps/madbridge/src/tui/components/RoomStatusBand.tsx` renders the TUI's own `room/projection.ts` over `@madventures/protocol`'s `RoomSnapshotBody`, not the room-status IR: a derived banner, the room's occupancy, block reason and input authority in Gateway terms, one row per execution in Gateway terms, and the qualifier "FIXTURE OCCUPANCY ONLY". Only `apps/madbridge/test/room-projection.test.tsx` uses it, and no screen mounts it.
3. `apps/madbridge/src/tui/App.tsx` shows `FixtureBanner` only when its `fixture` prop is true. `apps/madbridge/src/tui/main.tsx` sets that prop in `--fixture` mode and passes broker fixture data; no room snapshot reaches `App`.
4. `apps/projector-mc/src/lib/room-status.ts` holds a hand-copied mirror of the vocabulary, pinned by `apps/projector-mc/fixtures/room-status-vocabulary.pin.json` to Build Room `81d1203`. Its pin catches an edit on this side only.
5. Under this repository's settings the vendored files at Build Room `03cd29f` do not typecheck: `tsc` reports one error, TS2379 at `status.ts` line 226, because this repository sets `exactOptionalPropertyTypes` and Build Room does not. The root `tsconfig.json` has no `include`, so a separate `tsconfig` under `vendor/` cannot take the files out of the root check, and an import pulls them in regardless. A two-line, type-only change in Build Room clears the error and leaves Build Room's emitted output unchanged; `FOUNDER-ACT-20261103-BR-ROOM-STATUS-OPTIONAL-TYPES` makes it.
6. With that change, `@madventures/protocol`'s `RoomSnapshotBody` and the vendored one are each assignable to the other without a cast.
7. Both repositories are public, so CI can fetch Build Room's files at a named commit without a credential.

The drafting assistant checked items 5 and 6 in a scratch copy at the drafting base. That check is not this build's evidence.

B4. **The drift check.** It has two halves, sharing one script, `.github/scripts/vendored-room-status-check.ts`, which holds the repository and commit of B2 as constants:
1. **Offline**, run by `test/vendored-room-status.test.ts` inside `bun test`, and so inside Verify. 2. **Upstream**, run by one new job in `.github/workflows/vendored-room-status.yml` on every pull request to `main`. It obtains the six files from Build Room at the script's commit by `git fetch` of that commit from the public repository, with no credential, and fails when any vendored byte differs from them.

The job uses no secret except the custody token the Verify jobs already pass to `setup-qualified-bun`, only actions those jobs already pin, at the same SHAs, read-only `contents` permission, and a checkout that keeps no credential. A deliberate break of each failure path is made, shown failing and restored, with the restored file's SHA-256; such a break is not a change under B10. The job is not a required check on `main` unless a separate act of mine makes it one. Because the script is under `.github/`, a later re-pin changes a governance path and needs a Founder act naming its head.
