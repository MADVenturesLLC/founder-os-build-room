D-1 — RULING
D-1 is withdrawn. For the journal HTTP write path it is superseded by
Option B: a direct packages/control-plane caller of the landed
five-argument command_journal_append that reuses packages/journal's pure
exports, as PR #78 implements it. B-N2 (journal-append.ts), B-N3
(redaction-boundary.ts), B-T4, the SQL-side encoder and the r6
three-argument signatures are not to be built for this write path.
The D-1 ruling's RECONCILIATION sentences bind only a successor Gate
III draft that adopts D-1, and lapse with it. This withdrawal does not
depend on the supplementary Addendum-02 disposition PR #54 cites
(msg 9052), whose text is not in this repository.
C3 — RULING
The pre-write guard is accepted for PR #78: packages/journal's
normalizeForJournal redaction and a containsCredentialMaterial scan of
every caller-supplied string, both applied before any database contact.
packages/redaction's JournalAppendSink stays unwired. No Tranche D
cutover (moving DATABASE_URL to br_app_runtime) occurs until the
JournalAppendSink reconciliation named in the correction note's C3 has
been ruled and FD-3 key custody has been resolved. Until that cutover,
PR #78's identity latch refuses appends from every login other than
br_app_runtime.

  SHA-named act.

- It authorizes no Tranche D cutover, key provisioning, migration, Gate

- It does not alter the D-1 ruling or the correction note; both stay as
  landed.
- It changes no ratified decision in FounderOS.
