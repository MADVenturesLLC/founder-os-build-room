Part A: Basis
A1. Rows are stored as their canonical bytes, in the row_bytes column of command_journal_events (migration 0006_command_journal_authority_split). The fields are not columns, and the append routine takes the bytes as given. Two new fields therefore need no schema change and no migration.
A2. Every row's bytes begin with its spec identifier. decodeJournalRow in packages/journal/src/decode.ts selects the decoder from it. So the per-row marker the act's C2 says is missing already exists.
A3. Spec (c) says its golden vectors are generated by the implementation, never hand-authored. The ruling of 2026-09-01 on pull request 2a let the pure encoder ride with its spec for that reason. A documents-only pull request 1 cannot carry generated vectors.

Part B: Rulings
B1. C1. packages/control-plane/src/migrations.ts is removed from the paths. The two pull requests add no migration.
B2. C2 is replaced:

  - A chain in which a BRJ:c:1 command row follows a BRJ:c:2 command row fails verification.
  - Existing rows are never rewritten.
