`2222132d` stays enrolled in slot 1 with no daemon running, and the
Gateway code in the MacBook's old checkouts still reads its Keychain
items with `-w` if its `doctor`, `enroll` or smoke script is run (R3 of
the closing ruling).

**2. The PC's Gateway runs only while one terminal stays open.** B4 of
the restart act says so. The PC's previous boot ended at 07:30:20Z on
2026-10-14 with no shutdown entries in its journal; the cause is not
known. A supervised service is the act C5 of the to-done ruling directs
the builder to draft; it is not authorized.

**3. The posted to-done ruling kept its draft status line.** The text
reads "It has no effect until I sign it in the builder's session". It
took effect on the signature above, not on posting. It differs from the
builder's draft only in blank lines and line endings.

**4. The builder's draft of B3 reversed a standing ruling without
saying so.** As posted, B3 ruled the per-room ceiling exclusive,
against the Founder's ruling of 2026-08-29 in `DEC-20260815-16`. The
builder drafted it from `docs/planning/build-room-end-state/build-room-end-state-r1.md`
and `docs/phase-2-known-limits.md` section 9, both of which still
describe the question as open, and did not read the decision first. The
Founder amended B3, and the ruling of 2026-08-29 stands.
`docs/phase-2-known-limits.md` section 9 is not corrected by this
record.

**5. The signature's time is approximate.** It was given in session,
which leaves no GitHub timestamp. The builder's B1 reads were at
01:14:17Z and the daemon's first request at 01:17:07Z.

**6. Five values in the PC readings, and one in the builder's reads,
are masked.** This repository is public. In the Founder's readings, a
partial phone number in a Hermes log line, a Tailscale node key, a
Tailscale node id, a Tailscale tailnet id and a public IPv6 address are
each replaced by a bracketed `[masked: …]` label; nothing else is
changed. The builder's reads leave out the source address of the
Gateway's requests. The unmasked text exists only in the builder's
session. The MacBook outputs needed no masking.

Founder's shell ran v22.22.1; the PC enrollment record names v22.23.2.
The restart act ran the daemon through the v22.23.2 binary by its full
path, so the daemon ran under the recorded version.

**8. One pull request carries three acts' custody.** C1 of the to-done
ruling sets one custody filing per act; this record files the MacBook
act with its closing ruling, the restart act, and the to-done ruling
together, so that one merge carries all three.

**9. The merge of this record's pull request starts another
deployment.** Under C1 of the to-done ruling it gets no custody pull
request of its own; its authorization and post-merge verification are
filed with the next act's custody, or in the ops-actions log.
