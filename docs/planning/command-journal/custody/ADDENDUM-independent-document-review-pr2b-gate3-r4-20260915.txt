CORRECTION 1 (HISTORICAL — NEVER DISPATCHED) — the R3-to-R4 delta was stated in an ambiguous unit

The brief says: "R4 amends R3 by pure insertion: 18 hunks, 17 insertions
and one replaced line (the title designator)."

"17 insertions" is a hunk count. Read as a line count, which the
sentence invites, it cannot be reconciled with the sizes the brief
itself gives.

Line counts, from `git diff --numstat` between the two blobs on main.
These do not depend on how the diff is rendered:

  lines added      335
  lines removed    1      (the title designator, R3 -> R4)
  net              +334
  R3               2285 lines
  R4               2619 lines   (2285 + 335 - 1)

Hunk counts do depend on rendering, and the brief gave one as though it
were fixed. `--numstat` reports no hunks at all. Counting `@@` markers:

  18 hunks at --unified=0    (17 insertion + 1 replacement)
  14 hunks at the default -U3

Cite the line counts. Treat any hunk count as a description of one
rendering, not a property of the change.

"Pure insertion" is also loose: one hunk replaces a single line. The
claim to verify is that no R3 line other than the title designator was
changed or removed, and that R3's rows are retained rather than
replaced.

CORRECTION 4 (HISTORICAL — NEVER DISPATCHED) — the no-ambiguity constraint is scoped, which narrows it

The brief bars the reviewer from resolving an ambiguity by choosing an
answer. That bar is about gaps and contradictions found in the act: do
not paper one over. It is not about Q8, which deliberately asks for a
judgment on drafted text. This is a narrowing of the constraint as the
brief states it, recorded here as a change rather than presented as a
clarification. If Q8 cannot be settled from the document, say so and
name what is missing.

Likewise, "Reviewer: <your id>" on the output's last line is an
attribution of the review, not a signature field of the act. The bar on
filling signature or identity fields applies to the act.

CORRECTION 5 (HISTORICAL — NEVER DISPATCHED) — the verdict vocabulary had no way to report a brief defect

The brief fixes the first output line to PASS or REQUEST CHANGES /
DOCUMENT REVIEW FAILED. Both are verdicts on the act. A reviewer blocked
by a defect in the brief itself — for instance unable to locate the
implementation plan Q6 needs, which is exactly what correction 2
repairs — had no vocabulary for that, and would have had to return
REQUEST CHANGES against the act for a fault in the brief. That would
corrupt the record this review feeds.

A third first-line verdict is therefore available:

  CANNOT COMPLETE — BRIEF DEFECT

Use it when the brief or this addendum, not the act, prevents answering.
Name the question, name what is missing, and answer whatever other
questions you can. It is not a verdict on the act and does not count as
a failed document review.
