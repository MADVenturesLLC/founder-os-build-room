# Serialization contract (b) — PlanDoc digest, version 1

Status: implementation serialization specification under
`docs/command-journal-contract.md` v0.17 §6.2, ratified through the pull
request that carries it. Spec identifier, fixed inside the canonical
bytes: `BRJ:b:1`. This document creates no governance authority; on any
conflict the command-journal contract governs.

Implementation: `packages/journal/src/plandoc.ts`. Golden vectors:
`packages/journal/vectors/plandoc.json`, generated by the
implementation, never hand-authored.

## Purpose

Defines the canonical byte sequence of a PlanDoc and therefore
`plan_hash` = SHA-256 over these bytes, rendered as 64-character
lowercase hexadecimal with no prefix and no separators (contract §6.2).
`plan_hash` is the value G3 computes at T3 (`plan.submitted`), G5
matches at T5 (`plan.approved`), and the decision-class record carries
where its effective plan-bearing state requires it (contract §2, §7).

## Schema-agnostic by ruling (2026-09-01)

Ruled on the PR 2a derivation plan, escalation 1, recommendation (ii)
taken: this is a schema-agnostic canonical document-tree encoding. No
PlanDoc schema exists at the lane base, and defining one is step-4
substance. When the PlanDoc schema is ratified it constrains which
documents are valid — it never alters this encoding.

## Non-retroactivity (ruled 2026-09-01)

Later schema ratifications constrain documents, never encodings. Any
change to the byte grammar below requires a new spec version with a new
spec identifier, and golden vectors bind to the version that generated
them.

## Value domain

A document is a tree of: `null`, booleans, safe integers, strings,
arrays, and objects with string keys. Fractional or non-safe numeric
values have no canonical form and are rejected; a schema needing them
represents them as strings. Duplicate object keys cannot occur in the
value model; negative zero is rejected.

## Byte primitives

- `u32be(n)`: 4-byte big-endian unsigned integer.
- `utf8(s)`: the UTF-8 encoding of string `s`.
- `lp(s)`: `u32be(byte length of utf8(s))` followed by `utf8(s)`.

## Value encoding

Each value is a type tag byte followed by its content:

| Tag | Type | Content |
| --- | --- | --- |
| `0x00` | null | none |
| `0x01` | false | none |
| `0x02` | true | none |
| `0x03` | integer | `lp(decimal)` — canonical ASCII decimal, no leading zeros, `-` for negatives |
| `0x04` | string | `lp(value)` |
| `0x05` | array | `u32be(count)` then each element's encoding, in order |
| `0x06` | object | `u32be(count)` then, for each entry in ascending UTF-8 byte order of keys: `lp(key)` followed by the value's encoding |

Array order is the document's order and is never re-sorted; object
entries are sorted by the UTF-8 byte order of their keys, which is total
and locale-independent.

## Canonical byte sequence

`lp("BRJ:b:1")` followed by the encoding of the root value. The root
must be an object.

## Digest

`plan_hash` = SHA-256 over the canonical byte sequence, as 64-character
lowercase hexadecimal.
