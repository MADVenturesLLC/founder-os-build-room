# Serialization contract (c) — command-class event row, version 1

Status: implementation serialization specification under
`docs/command-journal-contract.md` v0.17 §6.2, ratified through the pull
request that carries it. Spec identifier, fixed inside the canonical
bytes: `BRJ:c:1`. This document creates no governance authority; on any
conflict the command-journal contract governs.

Implementation: `packages/journal/src/event-row.ts` with chain framing
in `packages/journal/src/chain.ts`. Golden vectors:
`packages/journal/vectors/chain.json` (the mixed chain), generated by
the implementation, never hand-authored.

## Purpose

Defines the canonical byte sequence of the complete command-class event
row — the exact bytes the chain hash covers (contract §4.1, §6.2):
field presence and order, scalar encodings, collection ordering
(`evidence_refs` in recorded order, never re-sorted), and the chain
framing.

## Chain framing and why it rides in 2a

`chain_hash` = SHA-256 over the prior row's chain hash rendered as its
64 lowercase-hex ASCII bytes (the 64-ASCII-zero genesis constant for
the first row) followed by the row's canonical byte sequence per this
specification or the (d) specification, as the row's record class
determines (contract §6.2). The framing function is pure and rides in
step 2a because the §6.2 chain vectors cannot be generated without it;
the production hashing path — the append protocol, the chain head, the
store — is step 2b, and none of it exists in 2a (ruled 2026-09-01,
condition 2 on the PR 2a derivation plan).

## Byte primitives

- `u32be(n)`: 4-byte big-endian unsigned integer.
- `utf8(s)`: the UTF-8 encoding of string `s`.
- `lp(s)`: `u32be(byte length of utf8(s))` followed by `utf8(s)`.
- `lpb(b)` (length-prefixed raw bytes): `u32be(length of b)` then `b`.
- String field: `[tag]` `[0x00]` when absent; `[tag]` `[0x01]` `lp(value)`
  when present.
- Bytes field: `[tag]` `[0x00]` when absent; `[tag]` `[0x01]` `lpb(value)`
  when present.
- Pair field: `[tag]` `[0x00]` when absent; `[tag]` `[0x01]`
  `lp(first)` `lp(second)` when present.
- Array field: `[tag]` `[0x01]` `u32be(count)` then `lp(item)` per item
  in recorded order; empty is present with count 0.

Field presence is structural — the `0x00` presence byte, never a
sentinel value. Every field below appears in every canonical form,
present or absent, so the grammar is positional and total.

## Event-type matrix

The closed vocabulary (contract §5.2) with row-level field legality.
"Required" and "allowed" refer to the optional fields `0x05`–`0x18`;
fields not listed as allowed must be absent. Cross-row rules — ordering
invariants, set-once identity, the §5.3 completion test — belong to the
2b append and verification layer, not to this byte specification.

| `event_type` | Required | Also allowed | Notes |
| --- | --- | --- | --- |
| `journaled` | `actor_id`, `role_id`, `repository`, `scope_ref`, `command_envelope`, `envelope_digest`, `authorization_ref`, `intended_provider`, `intended_model`, `intended_surface` | `room_id`, `run_id`, `execution_id`, `lifecycle_event_ref` | carries §2 elements 1, 3, 5–7, any element-2 identities that already exist, and the intended routing identity labeled as intent |
| `identity_bound` | at least one of `room_id`, `run_id`, `execution_id` | the other element-2 identities | carries only the identities it binds; `evidence_refs` must be empty; an `identity_bound` with nothing to bind is invalid |
| `dispatched` | `provider`, `model`, `execution_surface` | `room_id`, `run_id`, `execution_id`, `lifecycle_event_ref` | the observed actual routing identity, authoritative for §2 element 4 |
| `completed` | none | `lifecycle_event_ref` | |
| `failed` | `failure_classification` | `lifecycle_event_ref` | pre-send `failed` carries no observed identity; no `failed` row carries one — the observed identity lives on `dispatched` |
| `unresolved` | none | `lifecycle_event_ref` | |
| `resolved` | `resolution_determination`, `resolution_semantics` | `lifecycle_event_ref` | reconciliation evidence via `evidence_refs` |

Element-2 identities never appear on terminal events: they are recorded
exactly once, on `journaled`, `identity_bound`, or `dispatched`
(contract §2).

## Canonical timestamp and the named 2b obligation

`recorded_at` is RFC 3339 UTC with exactly six fractional digits and
the literal `Z` designator: `YYYY-MM-DDTHH:MM:SS.ssssssZ`. The date
must be calendar-valid: the day exists in that month and year under
the Gregorian leap-year rule. A calendar-impossible timestamp (for
example February 29 in a non-leap year) is rejected by the encoder and
has no canonical form — parsers that normalize such a date to a
different day must never be given the chance, so validity is checked
on the string itself. Rejected inputs produce no golden vector:
invalid inputs have no canonical bytes to record. Named 2b
obligation (ruled 2026-09-01, condition 3 on the PR 2a derivation
plan): the step-2b store must reproduce this canonical form
byte-identically on read — store the canonical string rather than
re-rendering from a timestamp type.

## Non-retroactivity

Any change to the byte grammar above requires a new spec version with a
new spec identifier; golden vectors bind to the version that generated
them.
