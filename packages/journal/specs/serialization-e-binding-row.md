# Serialization contract (e) — binding-class record row, version 1

Status: implementation serialization specification under
`docs/command-journal-contract.md` v0.19 §6.2(e), written under
FOUNDER-RULING-20261117-BR-JOURNAL-PHASE5 B2 and G2 (contract §13) and
ratified through the pull request that carries it. Spec identifier,
fixed inside the canonical bytes: `BRJ:e:1`. This document creates no
governance authority; on any conflict the command-journal contract
governs.

Implementation: `packages/journal/src/binding-row.ts`, the strict reader
`decodeBindingRecordRow` and the dispatch by spec identifier in
`packages/journal/src/decode.ts`, and chain framing in
`packages/journal/src/chain.ts`. Golden vectors:
`packages/journal/vectors/binding-row.json` and the chain in
`packages/journal/vectors/chain-binding.json`, which carries command,
decision and binding rows on one `seq` space. Both are generated by the
implementation, never hand-authored (contract §6.2), before anything
hashes a binding row in production (G2).

## Purpose

Defines the canonical byte sequence of the complete binding-class record
row (contract §2 "Binding-class records"; §13 B1, B2). The room binding,
lifecycle event `runtime_room.bound`, is journaled as a third record
class on the one chain. A binding record is a single event, terminal by
construction, with no state machine. Its element set is closed: the
event, `runtime_room.bound`; the actor, `system`; the three payload
fields FOUNDER-RULING-20261027-LIFECYCLE-ROOM-BINDING B2 fixes,
`lifecycle_room_id`, `runtime_room_id` and `gateway_id`; the recorded
lifecycle state, `BUILDING`; the `plan_hash` T5 bound; the
`lifecycle_event_ref`; and the timestamp, with the `seq` that places it
on the chain.

Contract §2 elements 4, 8 and 9 do not apply to the class, and element
1's `command_id` is not part of these bytes: the stored `command_id`
column of a binding row names the first Builder command, the one the
binding commits with (§13 B3, G4), and stays outside the canonical
bytes. The row shape has no slot for any of them, so no encoder can
emit them.

## Chain framing

`chain_hash` = SHA-256 over the prior row's chain hash rendered as its
64 lowercase-hex ASCII bytes (the 64-ASCII-zero genesis constant for
the first row) followed by the row's canonical byte sequence per the
(c), (d) or (e) specification, as the row's record class determines
(contract §6.2). A binding row is chained over the one `seq` space by
the same framing as command and decision rows.

## Byte primitives

Identical to spec (c): `u32be`, `utf8`, `lp`, string fields with
structural presence bytes (`0x00` absent, `0x01` present), and pair
fields (`[tag]` `[0x01]` `lp(first)` `lp(second)`). Canonical strings
are well-formed Unicode: a string containing a lone UTF-16 surrogate
has no canonical form and is rejected before encoding. Rejected inputs
produce no golden vector.

## Canonical byte sequence

`lp("BRJ:e:1")` followed by the fields below, in exactly this order:

| Tag | Field | Kind | Presence |
| --- | --- | --- | --- |
| `0x01` | `record_class` | string | required; always `binding`; the explicit class discriminator inside the canonical byte input (contract §2, §6.2) |
| `0x02` | `seq` | string | required; canonical ASCII decimal, no leading zeros, at least 1 — the one shared `seq` space |
| `0x03` | `event` | string | required; always `runtime_room.bound` |
| `0x04` | `actor_id` | string | required; always `system` |
| `0x05` | `lifecycle_room_id` | string | required; canonical lowercase UUID |
| `0x06` | `runtime_room_id` | string | required; `room-` followed by a canonical lowercase UUID |
| `0x07` | `gateway_id` | string | required; canonical lowercase UUID |
| `0x08` | `recorded_state` | string | required; always `BUILDING` |
| `0x09` | `plan_hash` | string | required; 64 lowercase hex |
| `0x0a` | `lifecycle_event_ref` | pair | required; (`room_id`, `event_id`), contract §1.4; `room_id` equals `lifecycle_room_id` |
| `0x0b` | `recorded_at` | string | required; canonical RFC 3339 UTC with exactly six fractional digits, as spec (c) defines |

A canonical lowercase UUID is 36 characters: five groups of `0-9a-f` of
lengths 8, 4, 4, 4 and 12, joined by `-`. No uppercase, no braces, no
`urn:uuid:` prefix, no other spelling.

## Presence

Every field is required. Each appears with the presence byte `0x01`
followed by its value; the class has no optional field, so no binding
row has an absent form of any field, and `0x00` in a presence position
has no canonical reading under this specification. A reader refuses it.
The grammar keeps the presence byte for every field anyway, so that
specifications (c), (d) and (e) share one positional field grammar.

## Validation

The encoder refuses, and produces no bytes for, any row in which:

- any field is missing or is not a string (the pair's two members
  included);
- `seq` is not canonical ASCII decimal at least 1;
- `event` is not `runtime_room.bound`, or `actor_id` is not `system`, or
  `recorded_state` is not `BUILDING`;
- `lifecycle_room_id` or `gateway_id` is not a canonical lowercase UUID;
- `runtime_room_id` is not `room-` followed by a canonical lowercase
  UUID;
- `plan_hash` is not 64 lowercase hex characters;
- `lifecycle_event_ref.room_id` differs from `lifecycle_room_id`: a
  binding names its own room's `runtime_room.bound` entry;
- `lifecycle_event_ref.event_id` is empty or whitespace only, or carries
  credential material as the journal's write-path guard detects it
  (contract §6.1, `packages/journal/src/redact.ts`);
- `recorded_at` is not the canonical timestamp on a calendar-valid date;
- any string is not well-formed Unicode.

A reader refuses bytes that do not begin with `lp("BRJ:e:1")`, whose
`record_class` is not `binding`, that are truncated or carry trailing
bytes, that hold a presence byte other than `0x01` in any field, that
hold invalid UTF-8, or that the encoder above would not reproduce byte
for byte from the row they decode to.

Cross-row rules are not byte rules and are not stated here: that the row
before a binding is its first Builder command's `journaled` row (B3),
that no two bindings share a lifecycle room or a runtime room (B5), and
that every Builder command names its room's binding (B6). They are
`bindingChainDefect` in `packages/journal/src/sequence.ts`.

## Canonical timestamp

As spec (c), in full: RFC 3339 UTC with exactly six fractional digits
and the literal `Z` designator, on a calendar-valid date (a
calendar-impossible timestamp is rejected and has no canonical form),
and the store reproduces the canonical `recorded_at` string
byte-identically rather than re-rendering it.

## Non-retroactivity

Any change to the byte grammar above requires a new spec version with a
new spec identifier; golden vectors bind to the version that generated
them.
