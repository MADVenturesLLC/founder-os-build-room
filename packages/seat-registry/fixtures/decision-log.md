# Decision Log

remote references and check `/07-decisions/decision-id-reservations.md`, per
`/01-constitution/decision-rules.md` §13 — a canonical identifier must be
unique across all active branches and workstreams, not just the commits
already present in this log.

**v4.45 (2026-08-30) — a fifth merge-path outcome recorded: correct trailers on a compliant PR body landed malformed on `main` because GitHub wrapped the merge-commit message; and a Founder-authorized line-length safeguard for future PRs.** Record-keeping for the incident; `main` is not rewritten. **What happened.** PR #316 merged at `24cd66a26e47ce803e7e8c2b2903a690606894b6`. Its PR body was verified correct immediately before merge — Attribution trailers end-anchored at column 0, `attribution-shape` green on the final head `2db2ab0`, Tier-2 `PASS-WITH-ADVISORIES` from `grok-4.5`. Post-merge verification against the merge SHA nevertheless returned `FAIL (c) final-merged-commit 24cd66a...: Role-Id present but Actor-Id missing`. **Cause, measured not inferred.** GitHub hard-wrapped the merge-commit message body. `Actor-Id: session:claude-code/dec-20260815-17-next-action-state-correction` is 74 characters and broke at its only space, leaving `Actor-Id:` alone on body line 273 and its value on line 274. The gate matches `^Actor-Id:[[:space:]]*[^[:space:]]`; a colon followed by a newline has no non-space character on that line, so the trailer reads as absent while `Role-Id` is present — clause 19(c) fails. **What the measurement does and does not establish — two readings were corrected, the second by Tier-2 review.** An initial reading treated 73 as a demonstrated-safe source length, because no *wrapped* prose line in the landed body exceeds 73. That was wrong and is withdrawn: those 71-to-73-character lines are the wrapper's *output*, produced by breaking long paragraphs, not source lines observed to survive. A second claim — that no prose line in the landed body exceeds 73 at all — was also wrong, and is likewise withdrawn: body line 221 is an unfenced 97-character line. **That line reveals the mechanism.** The wrapper breaks at spaces, and a token containing no space cannot be broken; line 221 is a single backticked path with no space in it, so it overflowed the column intact. The `Actor-Id` line at 74 characters contained exactly one space — the separator after the colon — and broke precisely there. That is why this is the fatal case rather than a cosmetic one: every attribution trailer contains exactly one space, so an over-length trailer always splits its value onto the following line, which is the shape the gate reads as absent. **What is directly evidenced.** Five trailer lines survived unchanged at 16, 27, 30, 35 and 56 characters, the longest being `Tier2-Head-Sha:` at 56; one failed, the `Actor-Id` line at 74. Nothing between 57 and 73 is directly evidenced either way, and the observation cannot distinguish "wrap beyond 73" from "wrap at 72 with a word permitted to overhang to 73." Lines inside fenced code blocks are exempt and survived at up to 123 characters, but trailers cannot be fenced. **This is a new failure class, not a repeat.** `DEC-20260721-01` records that observed merge outcomes have varied by technique and that no merge path is established as safe; this instance adds a cause independent of technique — message *width*. PRs #314 and #315 passed post-merge verification with the identical merge path and identical trailer shape; their `Actor-Id` values were simply shorter. Nothing about how the merge was performed differed. **Why no gate could catch it.** The pre-merge `attribution-shape` run evaluates the PR body and the branch commits. The merge commit does not exist at that point, and its message is produced by GitHub at merge time.
